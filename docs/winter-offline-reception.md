# Winter：通信中断時にiPadで受付を預かる

## 当日の操作

1. 当日使うiPad・Safari／ホーム画面アイコンでWinter受付を開く。同じURL・同じ開き方を使う。
2. 通信中に「大会本部」へログインする。**ログインすると、画面・名簿・競技・参加区分・料金・出番の準備を自動で開始する。準備用のタブやボタンを開く必要はない。** 本部のどのタブでも上部に状態が表示される。
3. 上部の「オフライン受付の準備完了」、大会名、取得日時を確認して「受付画面へ」で戻る。来訪者画面には「オフライン受付の準備済み／このiPadに預かる受付」と表示される。このとき端末の本部ログインを解除する。
4. 通常の追加・変更・棄権画面で入力し、最後に来訪者のお名前を一度入力。「このiPadに受付内容を保存」を押す。
5. 「このiPadに受付内容を保存しました」「受付番号」「本部への送信待ち」の表示を確認して、次の方・別の団体へ進む。保存失敗時には進まない。
6. 管理者が戻り、通信が復旧したら再ログイン。「申請一覧」上部の「このiPadに未送信の受付があります」で件数を確認し、「内容を確認する」を押す。本部の受付状況との照合後、内容を確認して「確認した未送信分を申請一覧へ取り込む」を押す。回線復旧や内容確認だけでは送らない。
7. 取り込みが成功すると「申請一覧に登録済み」と表示され、同じ画面の下の申請一覧が更新される。出番表への反映は従来どおり申請一覧の反映ボタンで行う。登録済みでも端末の記録は自動削除しない。

**準備済みモードでは通信中も端末に預かり、管理者が送信する。** その日の受付開始前は、本部へログインして自動準備の完了を確認する。未送信の保存済み受付は準備の更新で消えない。

### 自動準備の表示

- **準備中**：保存と読み戻しの途中。完了まで通信をつないで待つ。
- **準備完了**：今回の画面とデータの準備を確認できた。受付へ戻れる。
- **入力中の受付があるため待機**：同じ未確定一覧を確認して端末に保存し、本部へ戻ると自動で再開する。別タブで入力を終え、本部画面を開いたままなら、その変更を検知して再開する。入力内容を消して準備を優先しない。
- **通信の復旧待ち**：本部を開いたまま回線が戻ると自動で再開する。
- **準備を完了できない**：エラー内容を確認し、表示された「準備を再試行」を使う。今回の更新は未完了として扱い、保存済み受付を消さない。

本部ログイン中に保存済みの名簿・出番等の更新を受け取った場合も自動準備する。実行中の更新通知はまとめて処理し、タブの切替や認証トークン更新だけでは繰り返さない。本部を離れる／ログアウトする間に準備が続いていた場合は、新しいデータを書き込む前に中止する。アプリを閉じた状態での準備や、受付の自動送信は行わない。

## 状態と訂正

「端末に預かった受付」の独立タブは廃止し、「申請一覧」に統合した。端末に受付記録がなければ案内は表示しない。記録があれば追加・変更・棄権の内訳と状態別件数を表示する。通信中も端末に保存するため、「オフライン時」に限定した表示にはしない。ほかのiPadにだけ保存されている未送信受付は、この端末からは見えない。

詳細は「内容を確認する」で管理者権限を再確認して開く。このとき本部と照合するが、未送信分は取り込まない。読み取りに失敗した場合は保存内容を残し、取り込みボタンを無効にして「本部の受付状況を確認する」から再確認する。タブ切替・画面のバックグラウンド移動で詳細を閉じる。従来の `#winter-offline-reception` リンクも「申請一覧」を開く。

- **端末に保存済み・本部未受付（未送信）**：端末に保存済み。本部への保存はまだ。
- **要確認**：出番・所属・参加情報・競技料金の変更、同じ出番への複数申請など。該当分だけ止まり、独立した申請は送れる。
- **結果確認待ち**：送信途中の中断などで届いたか不明。「結果を確認する」で同じ受付番号・申請IDを照合する。保存が確認できれば追加送信せず登録済みになる。未解決なら「同じ受付番号で取り込みを再試行」を使う。別の受付として作り直さない。
- **申請一覧に登録済み（保存上の状態は従来のsent）**：同じ番号・内容で本部の保存成功を確認。出番表への反映済みを意味しない。出番表への未反映／反映済み／取消済みは既存の申請一覧で確認する。
- **端末内で取下げ**：未送信と確認できた申請を管理者が理由付きで取下げ。記録は残る。

最新情報と照合した後、未送信／明確に拒否された申請は管理者が人馬・競技・参加区分・来訪者などを訂正できる。訂正前の内容と理由を端末に保持し、最新の所属・出番・金額を確認してから保存する。結果不明の申請は、保存結果が確定するまで内容・IDを固定する。本部にすでに保存された申請の訂正は既存の本部操作を使う。

## 通信中断中にできないこと・注意

- **本部・審判には届かない。出番が迫る申請は電話や係員を通じて別途連絡する。** 画面にも常時表示する。
- 出番表、精算、他端末への反映、確定精算・入金はオフラインでは行わない。
- 保存済み名簿にない人馬は推測で登録しない。本部で確認する。
- 初めて開く未準備の端末は対象外。準備完了前に通信を切らない。
- プライベートブラウズは使わない。Safariとホーム画面で保存領域が異なる場合があるので、実際に使用する方で準備・試験する。
- 故障・紛失、サイトデータ消去、OSによる領域削除、極端な容量不足・電源故障は端末保存だけでは保証できない。空き容量を確保し、未送信がある間は履歴／サイトデータの消去や端末初期化をしない。
- 新しい画面の更新待ちが表示された場合は、受付を保存してからWinterの他のタブを閉じ、同じURLで開き直して通信中に準備する。未送信受付は消去しない。
- 一般の来訪者に未送信一覧を見せない。管理者の確認・送信後は必ず来訪者用画面に戻す。端末そのものへの物理アクセスは管理する。

## 実機で残る確認（開発側の模擬試験とは別）

受付用iPadで、本部ログインと通信のオン／オフを操作する必要がある。識別された最小限のダミー団体・人馬だけを使用する。

1. 通信中に本部へログインし、追加操作なしで自動準備が始まり、大会名・取得日時・準備完了が表示されることを確認。
2. Wi-Fi／モバイル通信を切り、複数団体の追加・変更・棄権を保存。受付番号を控える。
3. オフラインのまま再読み込み、スリープ復帰、ブラウザーを閉じて開き直す。次の受付ができることを確認。
4. 通信を戻し、自動送信されないことを確認。
5. 管理者が照合して送信。未送信・要確認が残り、同じIDの記録と請求が重複しないことを本部で確認。
6. 別のダミー申請を送信中に通信を切る。復旧後、同じ番号で結果確認・再送し、重複がないことを確認。

実機確認は未実施の間、合格扱いにしない。
