# Winter：端末保存と本部への自動送信

2026-10-31の自動送信承認を反映した現行手順。PR #23〜#26の保存・自動準備・申請一覧統合を継承する。過去の「通信復旧後も管理者がiPadで送信する」手順は、保存を完了した受付について下記に置き換える。

## 当日の操作

1. 実際に受付に使う端末の、いつものSafari／ホーム画面／Chromeで固定Winter URLを開く。同じURL・同じ開き方を使う。
2. 通信中に本部へ本人ログインし、自動準備の完了・大会名・取得日時を確認する。準備専用のタブや必須ボタンはない。「受付画面へ」で戻ると本部ログインを解除する。
3. 来訪者が通常の追加・変更・棄権を入力し、最後に名前を入力して「この端末に受付内容を保存」を押す。保存完了と受付番号を確認して次の方へ進む。入力途中の内容は送信しない。
4. 通信中は保存完了分を本部へ自動送信する。通信断中は端末に保持し、復旧時に自動再開する。iPadで本部に再ログインしたり、管理者送信を押す必要はない。
5. 本部PCでは全タブの上部に「未反映の申請／要確認」を表示する。「申請一覧で確認する」から内容を確認する。通常分は既存の申請一覧、料金・出番等が変わった分は「本部に届いた要確認の受付」に表示する。
6. 出番表への反映、精算・入金は従来どおり本部の確認操作で行う。自動送信はこれらの確定を行わない。

## 準備と通信の状態

- 自動準備は本部ログイン後に開始する。入力中の受付がある場合、その入力を保持して準備更新を待つ。同じ未確定内容を保存して本部へ戻ると再開する。
- 保存済み受付の自動送信は準備更新とは独立して動く。入力中の別受付があっても、保存済み分は送れる。入力途中の受付を勝手に確定しない。
- 受付アプリを開いている間に送信する。端末がスリープ中、ブラウザーを閉じた間、OSが停止している間の送信は保証しない。画面に戻ると同じ番号で再開する。
- 通信復旧イベントと画面復帰で再確認する。失敗時は15〜60秒の間隔で再試行する。ブラウザーが通信中と表示しても、本部応答が確認できるまでは送信・結果確認待ちとする。
- 本部PCは表示中に約15秒ごと、通信復旧時、画面復帰時に件数を確認する。取得失敗時は前回件数とエラーを表示し、0件として扱わない。
- 本部に届いていない端末内の受付件数は、別PCから取得できない。**通信断中に出番が迫る申請は本部・審判へ電話や係員を通じて別途連絡する。**

## 要確認と再送

受信した元の内容は本部の非公開領域に保持する。既存の出番・所属・料金・重複チェックを通れば申請一覧に未反映として登録し、通らなければ本部の要確認一覧へ送る。要確認でもiPad側の管理者操作を待たない。

本部管理者は既存の訂正フォームで最新の名簿・出番・金額を確認し、理由を付けて申請一覧へ登録するか、その要確認受付を取下げとして記録する。元の受信内容・受付番号・申請IDを保持する。取下げは別の既存申請や出番を取り消す操作ではない。

通信中断で結果が不明な場合は、同じ番号・同じ内容で再確認する。別の受付として作り直さない。本部の確認操作も結果不明時は内容を固定し、「同じ内容で確認結果を再確認」を使う。

端末の保存記録も自動削除しない。本部受信確認済みの記録は端末側の未送信一覧から外し、本部で処理する。以前の形式の保存記録・編集履歴は維持する。申請一覧内の端末確認欄は、送信待ちが続く場合の確認用として残す。独立した「端末に預かった受付」タブはない。

## 端末運用と残る実機確認

プライベートブラウズは使わず、サイトデータを消去しない。故障・紛失・OSによる保存領域削除・容量不足は端末保存だけでは保証できない。旧画面の更新待ちが出た場合は、保存済み／入力中内容を保持したまま同じ入口で更新する。

実iPadで未判定の範囲は、通信なしでの「入力を続ける」「次の方」への移動、スリープ／再起動後の継続、今回の自動送信、送信途中切断の復旧。本部PCの準備完了は利用者画像で確認済み。管理試験①②③や完成済み機能を再試験しない。

利用者が既に入力したオフライン試験の内容を再利用し、受付番号を変えず保存する。担当は本部DBを読み取り、保存番号・申請ID・種別・金額・重複・出番未反映・入金未操作を照合する。実機合格はその結果が得られるまで保留する。詳細記録は `winter-offline-verification-20261030.md` と `winter-automatic-delivery-20261031.md` を参照。
