# Excel取込画面で人馬の所属を訂正・移動

## 動作

③の既存名簿訂正欄で、名前・読み・日馬連番号に加えて所属を訂正できる。差分のない登録済み人馬にも「名簿の名前・番号・所属を訂正する」を表示する。

- 所属先の第一候補は取り込み中のクラブ。指定方法を「登録済みクラブの一覧から選ぶ」「クラブ名を手入力する」に切り替えられる。
- 既存一覧はクラブIDで選択。手入力で完全一致する既存名があれば、そのクラブを使用する。
- 移動前の所属のうち、利用者がチェックした所属だけを終了する。未チェックは兼所属として保持。移動先自身は終了できない。
- 保存前に変更前・変更後・終了する所属を表示し、同じ人馬であることを確認して保存する。入力を変えると確認を解除する。編集中の所属指定は確認下書きに保存でき、古いJSONとの互換性を保つ。
- 実人馬をこの作業では移動していない。正しい所属は利用者が選択・確認して保存する。

## 大会での所属・請求との関係

共通名簿の現在の所属と、既に登録したWinter大会内の参加団体・請求先を分ける。所属変更で既存の人馬ID、Winter参加、対応する受付人馬ID、出番、団体、請求・入金は移動しない。名前・番号の訂正は前回の機能どおり同じ人馬のWinter記録へ反映する。

移動後でも、申込クラブに保存済みのWinter参加があれば、それを使用して追加取り込みできる。申込クラブへの現在所属も保存済み参加もない場合は要確認のままにする。申込クラブと別の所属先を指定すると、この違いを画面に表示する。任意の別クラブへ出番・請求先を自動転送したり、旧所属を自動で再追加したりしない。

## 保存処理

Supabase生成版 `20261024144609_winter_roster_affiliation_correction` を適用。送信したSQLと保存したmigrationの全文一致を確認した。

既存の訂正RPCに所属先IDと終了する所属IDを追加。新しいテーブル、ACL、役割設定の変更はない。省略した旧クライアントの要求は従来どおり所属追加のみ。同じ要求IDの再送は以前の要求も含めて同一内容だけ成功する。

管理者検査、Winterイベント固定、SECURITY INVOKER、固定search_path、ID・更新日時・所属・Winter参加状態の比較、トランザクションロックと監査履歴は保持。対象人馬の有効な所属だけを終了できる。指定先のクラブID・名前の組合せ、終了所属と移動先の重複、別IDの日馬連番号重複を検証する。送信前に端末保存し、送信後はサーバーを再取得して所属集合と保持対象の完全一致を確認する。

## 検証

関連13本のCJSスイート、TypeScript検査、24ページのwebpackビルド、diff検査を通過。Autumnの精算画面・印刷HTMLとの完全一致比較も含む。

実コンポーネントとフックの合成操作では、差分のない既存人馬から所属変更を開始し、既存一覧選択、旧所属終了、変更後の再照合、手入力の新所属追加、兼所属保持、下書き往復、続く追加エントリー取り込みまで確認。既存参加団体と受付IDを維持し、共通名簿の現在所属だけが変わることを検証した。候補を変えた場合は別ID用の所属編集を消去する。

migrationと同じトランザクション内で前回の名簿訂正SQL試験と所属移動のSQL試験を実行。旧所属の履歴、選択した所属だけの終了、兼所属保持、手入力先作成、既存先再利用、再送、移動先終了拒否、終了済み/不明ID拒否、所属先IDと名前の不一致拒否、既存参加先保持を確認した。合成行は成功時もサブトランザクションで取り消す。

名簿・クラブ・所属・参加・対応・人馬・出番・団体・初期請求・入金・資格・訂正履歴の13表は、適用前後の件数と全行ハッシュが一致。既存の訂正履歴も保持。Security advisorsは観測時刻を除き既存54件と一致し、新規指摘なし。
