# Excel取込画面で保存済み人馬名簿を訂正

## 動作

既存名簿の誤字・日馬連番号未登録・所属不足が原因で③の取り込みが止まった場合、同じ行から既存人馬を選び、正しい名前・読み・番号を入力して「既存名簿を訂正・所属を保存」を押せるようにした。変更前・変更後と所属の追加先を表示し、同じ人馬であることを確認してから保存する。入力を変えると確認は解除される。Excel原本へ戻す操作も用意した。

名簿が正しく申込だけを直したい場合の「名簿の表記を使う」は補助操作にまとめた。通常の未確定入力では別画面への移動を要求しない。名前や番号が同じ既存候補を訂正するために、新規人馬を作る必要はない。別のIDが同じ日馬連番号を持つ場合は、その番号付き候補を選んで所属を追加するよう案内し、自動統合しない。

## 保存

利用者から既存名簿の訂正・登録をこの画面内で行えるよう明示依頼を受け、専用RPCと履歴テーブルを追加。適用バージョンはSupabaseが生成した `20261024132016_winter_roster_identity_correction`。既存の保存RPC・既存の権限・アカウント設定は変更していない。

- 既存IDを保持し、共通名簿の名前・読み・日馬連番号を訂正。申込団体の所属を追加し、既存の他所属は保持する。
- 同じIDの既存Winter参加スナップショットと、対応するWinter選手・馬の名前と番号を原子的に同期。既存の受付ID、参加フラグ、所属団体、出番、請求、入金を変更しない。Autumnの人馬スナップショット・本番サイトは対象外。
- SECURITY INVOKER、固定search_path、サーバー管理のapp_metadataの管理者条件。匿名実行不可。履歴は管理者のみ読取・追加可、ブラウザー利用者のUPDATE/DELETE不可。
- 名簿更新日時・所属・Winter参加・対応先・表示名・番号・団体・参加状態を、利用者が確認した値と比較。別操作で変わったら上書きしない。参加登録と同じトランザクションロックを使用。
- 同じ要求ID・同じ内容の再送は履歴を増やさず成功。同じIDで内容を変えた再送は拒否。番号重複も拒否。
- 送信前に確認下書きと版付き要求記録を端末へ保存。保存失敗ならDB要求なし。保存後にサーバーを読み直し、選択ID・訂正内容・保持対象が一致した場合だけ成功を表示する。通信応答を失っても照合し、自動再送しない。
- 訂正後に③の結果を更新。必要な請求額確認も同じ③に残し、再確認後に取り込みへ進める。確定済みの再開記録の入力固定は維持。

## 検証

19本の関連CJSスイートとAutumn精算HTML比較、24ページのwebpackビルド、TypeScript検査、diff検査を通過。

実コンポーネント・フックと合成サービスで、保存済み選手名の訂正、番号付き別IDの選択と所属追加、二重クリック、確認後編集、保存前端末エラー、権限エラー、保存応答喪失、競合時の最新値表示、原本保持、訂正から出番取り込みへの連続操作を確認。新規人馬作成は0件で完了する。

Supabaseではマイグレーションの同一トランザクション内で、認証済みロールと架空人馬を使うSQL試験を実行。複数所属、複数Winter参加先の同期、ID保持、番号追加、選手名訂正、再送、古い比較元拒否、イベント違い拒否、別IDの番号重複拒否、Winter側だけの競合、非管理者/ユーザーメタデータの役割偽装拒否を確認した。成功時も試験用行をサブトランザクションで全て取り消し、失敗時にはDDL全体がコミットされない構成。

適用後に試験用名簿0件、訂正履歴0件を読み戻した。名簿・所属・参加・対応・人馬・出番・団体・初期請求・入金・資格の12表は適用前後の件数と全行ハッシュが一致。実人馬の訂正は実施せず、利用者が正しい内容を入力・確認して保存する。Security advisorsは既存54件のままで、新規指摘なし。

実行環境に実ブラウザーがないため、実Excelを使った画面上の最終操作は未実施。描画HTML・イベント・状態遷移、DBでの保存・権限・競合試験、型・ビルドを検証範囲とする。実原本、実名、画像、認証情報、実データの控えはGitHubへ送らない。
