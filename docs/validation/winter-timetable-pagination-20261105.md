# タイムテーブル印刷の2ページ化への対応（2026-11-05）

## 利用者からの報告

PR #33 の反映後、Windows Chromeの印刷プレビューが「2枚」になった写真を受領。全日程の見出しがあり、1枚目の障害表は第26競技付近まで、2枚目も生成されている。日付・タイトル・ページ番号のブラウザー側ヘッダー／フッターが有効。選択先は iR-ADV C3826。プリンターの詳細な用紙・倍率・余白設定とChrome版は未取得。

前回の「PDFでは1ページ」という確認は利用者の印刷環境まで保証できていなかった。旧方式でヘッダー／フッター付きのPDF出力も調べたが、この環境では同じ2ページ化を再現できなかったため、個別の原因を確定したとは扱わない。

## 修正

基点は `prep/winter-2026` の `30cf5182d650361d3563e4b57f9e6853cb13b75c`。

共通 `lib/master/timetable-print.ts` の印刷レイアウトを修正した。以前は絶対配置した表を `transform: scale()` で見た目だけ縮小し、固定高の外枠に `overflow:hidden` を付けていた。今回は通常の文書配置と `zoom` を使用し、改ページ判定の対象になる配置自体を縮める。内容を切り落とす指定は削除する。

フォント読み込み後と印刷直前に毎回元の倍率へ戻して計測し、A4横の範囲に縮小する。フォント寸法の丸めに備えて縮小後の幅・高さも再確認し、必要なら追加調整する。外枠の高さは実際に縮んだ内容に合わせる。繰り返し印刷で倍率を重ねない。収まる寸法を確認できなければ印刷開始を止める。

日程選択・最新の保存済みデータの再取得・各日単独の印刷・既存の時間編集・共通マスターを維持。DB、時間、出場数、出番順、料金、入金への書き込みはない。

## 検証

- 内容検証 `winter-timetable-print.cjs` と選択操作 `master-timetable-selection.cjs` が成功。
- 印刷検証を拡張。画面表示から実際の `beforeprint` コールバックを経由し、ブラウザーの日付・ページ番号付き／なしの両方をPDF化する。画面用ツールバーが印刷されないことも確認する。
- Chromium 129 / 153それぞれで全7通りの日程選択、および長い競技名・確定表示を持つ40競技を確認。各16条件、合計32条件すべてA4横1ページ。各競技名全文と最後の脚注がPDF本体から抽出できることを確認した。単なる画面上の要素数やページ数だけの検査ではない。
- 土日36競技、全日程40競技、ヘッダー／フッター付き全日程を画像化し、最後の障害第31競技・馬場第36競技・注記まで目視確認。合成データを使用し、実際の申込や時刻を変更していない。
- TypeScript検査、Nextビルド、Winterオフラインシェル185アセット生成が成功。
