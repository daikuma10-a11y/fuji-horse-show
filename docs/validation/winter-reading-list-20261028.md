# Winter entrant reading list and stable checklist proposal

The Winter admin start-list tab now opens a reading list for the entire event and prints it on A4. Riders and horses are separate tables with name, reading, affiliation and JEF number. Only identities used by non-withdrawn/non-cancelled entries are included. Repeated appearances are deduplicated through the existing Winter identity bridge; equal names alone do not merge records. Missing readings are explicit. Kana-only horse names use the already approved kana reading fallback.

The new presentation and contract live in `components/master/reading-list.tsx` and `lib/master/reading-list.ts`; Winter supplies its data adapter. Reads reuse existing authenticated roster functions. No schema, registration, payment or affiliation writes are added. Loading, errors and stale roster results disable printing. Print layout also releases the full-screen fixed container.

Validation: TypeScript passed; `winter-reading-list.cjs`, `winter-start-list-layout.cjs`, `winter-entry-intervals.cjs`, and `winter-registration-overview.cjs` passed. Next.js webpack production build passed. Local Turbopack could not use a node_modules symlink outside the worktree; no application config was changed. Browser installation failed because the supplied download was not a valid zip, so physical iPad/Chrome printing remains untested. A read-only database query verified that the current entrant bridge can resolve stored readings; no records were changed.

The stable-checklist layout remains a proposal as requested: A4 portrait, four club cards, nine horses per card, horse-level arrival/departure dates, verification boxes, notes, veterinarian signature and collector signature. The PDF uses explicitly fictitious clubs/horses and was visually checked at A4 size. Actual club data binding and overflow continuation cards should follow the user's layout review. Recreate the proposal with `python scripts/winter-stable-checklist-preview.py --font /path/to/Japanese.ttf --output /path/to/preview.pdf`.
