# Winter保存処理の検証（2026-10-08）

## 実施済み

- Winter専用 `submit_winter_reception_add` をDBに追加。既存Autumnのポリシー・関数は変更していない。
- 本部管理者の認証チェック、Winter大会ID固定、所属・公認資格・OP・会員料金の検証を関数内で実施。
- トランザクション内の架空人馬を使い、認証なしの拒否、会員区分未選択の拒否、競技5の会員料金5,000円＋追加手数料3,000円の保存を検証。
- 同じID・同じ内容の再送が1件のままになること、同じIDで内容が異なる再送が拒否されることを検証。
- 検証トランザクションはROLLBACKし、テスト人馬・申請を残していない。
- 本部用の団体・選手・馬登録RPCを適用し、認証なし拒否、団体の重複登録防止、Winter所属保持、未確認の日馬連番号の拒否をROLLBACK付きで検証した。
- 実際の公開REST APIでWinterデータ読み込みを実行し、競技40件と団体・人馬0件を確認した。
- 画面に本部ログイン・人馬登録・追加確認・保存・受付番号表示を接続した。
- DBアドバイザーの新関数に対するSECURITY DEFINER実行警告は意図した本部専用RPC。関数内でauth.uidとapp_metadataのadminロールを検証し、anon実行は拒否。
