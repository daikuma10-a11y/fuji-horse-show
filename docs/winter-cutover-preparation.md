# Winter切り替え準備（2026-10-08）

対象：2026 Fuji Horse Show Winter Grand Prix★、11月13〜15日、締切11月2日。
この準備ブランチは稼働中のAutumn画面・DBの設定を変更しない。

## 確認済みの状態

- mainの最新はa44b464（10月7日の精算書簡略化）。Winter切り替えコードは未反映。
- Winter大会は9月21日に作成済み。ID: b571f05e-ed23-4e07-929e-be2b73e601a5、status=setup。
- Winter競技31件。第1〜22、第32〜36、フレンドシップ①〜④。第23〜31は未登録。
- Winter団体・選手・馬・エントリー・受付申請は各0件。
- 第5・8・32競技はfee=0。条件別料金の未設定として扱い、無料と解釈しない。
- Autumnは団体48、選手226、馬134、出番535、申請144。Winterへコピーしない。

## 実装する順序

1. 大会設定を共通化。大会ID、日付、表示名、振込先、ブラウザ保存キーを大会単位にする。
2. Autumn固定のseed、所属対応表、団体統合、人馬ID変換をWinterに流用しない。WinterのDBマスターから読み込む構造へ変更。
3. 出番番号をnumberのみで処理する構造を見直す。丸数字①〜④を独立した競技IDで保持し、NaNや通常競技との重複を防ぐ。
4. 第5・8・32の条件別料金を、最新版申込書の区分と照合して実装。第23〜31の名称・日付・公認区分・料金を原本照合して追加する。
5. 公開view、RLS、受付反映・取消・並替・新規人馬・打合会RPCのAutumn固定IDを確認し、Winter用の大会境界と管理権限を検証する。
6. 精算Edge Functionの大会IDをサーバー側設定で揃える。クライアントが送る大会IDを無条件に採用しない。Cookie/端末tokenも大会単位に分ける。
7. 正式申込データの取込手順と照合表を作る。11月2日の締切までは名簿・出番を確定しない。
8. Winter用Excelテンプレート・領収書名・日付・銀行情報を揃える。Autumnテンプレートへの書き込みを避ける。
9. 独立環境で受付→追加/変更/棄権→反映/取消→出番移動→モニター→精算保存→再印刷の通し確認を行う。
10. 本番切り替え時は旧大会を保存したまま、同じ大会IDでフロント/DB/Edgeを一致させる。失敗時は旧設定へ戻せるようにする。

## 切り替え前の必須条件

- requiredCompetitionNumbersをすべて原本と照合済み。
- 条件別料金の資格・会員区分が確定し、入力不足を0円にせず受付を止める。
- 正式名簿・出番・事前支払の件数と金額が原本に一致。
- 他大会の申請・支払・仮入力・打合会草稿・取消履歴が混入しない。
- 精算は利用者が操作可能、出番編集・金額修正は管理者のみ。
- 印刷は現在のiPad印刷画面を使用。直接印刷の中継は今回対象外。
